retraject re-tracing a 1997 thesis

In 1997 I finished a bachelor thesis at the "Politehnica" University of Timișoara: trajectory planning and control for a stepper-driven robot called the RIP02. The mathematics computed how each joint should move; an interrupt handler hooked to the PC's timer chip pulsed the motors through the parallel port; the interface ran on a DOS clone of Sun's XView toolkit, in EGA graphics. Twenty-nine years later, the code still existed — a folder of 8.3-character filenames in an archive of my university work — but nothing in it could run anymore. This project brought it back. Not as an emulation: as a re-derivation, verified, running live in your browser.

What survived, and what never existed

Reading the old sources (they are preserved verbatim in the repository's legacy/ folder) revealed a clean three-layer design: five interpolation laws describing how a joint eases from one position to another; a synchronization layer stretching every joint's motion so all axes of the robot start and finish together; and an execution layer that quantized the result into motor pulses. What the archive did not contain was the inverse kinematics — the mathematics that converts "put the tool here" into joint angles. Waypoints were typed in per joint, in motor steps; the IK existed only in the printed thesis, now lost to time. Rebuilding it from scratch became the heart of the revival.

One function instead of fifteen

The 1997 code gave every law three methods — compute position, compute speed, compute acceleration — fifteen sampling loops in all. The modern port rests on a single observation: every law is just a normalized shape r(τ), the fraction of the move completed at fraction τ of the time. Position, velocity and acceleration all follow from the chain rule, identically for every law — and stretching a motion in time automatically scales velocity by 1/T and acceleration by 1/T², which makes multi-axis synchronization a one-liner. The layer the thesis was actually about

The revival's six-axis arm (the kinematics explorer) has a spherical wrist — three wrist axes meeting in a point — because that is the property that makes closed-form inverse kinematics possible: the position problem decouples from the orientation problem at the wrist center. The solver enumerates all eight ways the arm can reach a pose (shoulder front/back × elbow down/up × wrist flip), and dragging the target runs it on every frame. Every solution is tested by feeding it back through the forward kinematics: one wrong sign anywhere in a page of trigonometry, and some branch fails to reproduce its target. A damped-least-squares numerical solver — built from nothing but derivatives — independently lands on the same answers. Try the taught-path demo, or the blended version that rounds the corners and, counterintuitively, arrives sooner.

Archaeology with tests

Porting thirty-year-old code with a test suite turns nostalgia into measurement, and three findings stand out. First, the original formulas were right: the quintic 10τ³−15τ⁴+6τ⁵ turns out to be the classic "3-4-5 polynomial" of cam design and the minimum-jerk trajectory of motor-control research, and every minimum-time expression matched today's literature. Second, a latent unit bug meant every 1997 trajectory was sampled at exactly 20 points regardless of settings — invisible then, obvious under tests now. Third, and my favorite: when I modeled the pulse quantization faithfully and asserted one-step accuracy, the test failed at eleven steps. Not a porting bug — the real 1997 behavior. One countdown constant per division floors the step rate, and the motor visibly ripples around the ideal curve. The fix already existed in my own earlier lab work, which had computed a constant per step; the thesis compressed it to save memory and paid in ripple. The virtual stepper lets you toggle between the two schemes — next to a faithful reproduction of the DOS console where this layer lived, white on blue, asterisks and all. It is the first graphical rendering this algorithm has ever had.

Coda

The mathematics a 24-year-old derived for a parallel-port stepper rig now runs, verified by 121 tests, on any device with a browser. The archive that preserved it, the analysis that revived it, and every design decision along the way are documented in the repository — the documentation lives next to the code it explains, so the project can teach what it taught me.
